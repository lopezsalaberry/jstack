# Operating model

How jstack behaves in practice today. Skills keep the detailed rules; this page
is the map. Where an open PR changes a skill, it is noted.

## Iteration policy (no fixed attempt cap)

Replaces the old "3 fix attempts, then block" cap. The skills workers
actually read implement it: see `skills/iterate/SKILL.md` (loop, verdicts, stop rules). Until 2026-11-02
`fanout`, `babysit-pr`, `full-send` and the `AGENTS.md` template still said "3 attempts" and workers
obeyed them, stopping minutes into real work; `tests/test_policy.py` now keeps them from drifting.

- **Fresh session per iteration.** Each iteration starts from the ticket's
  `RUNSTATE.md` (what was tried, what is known, next step), not from chat history.
- **WIP commit on progress.** Any iteration that moves the ticket forward ends
  with a WIP commit and an updated `RUNSTATE.md`.
- **Same failure twice = test the premise.** Write down the assumption behind the
  approach, test it directly, then pivot the approach or the model.
- **Environment failures do not count.** A broken tool, sandbox, or harness gets
  fixed; it never consumes the ticket's budget.
- **Limits are budget, not attempts.** Quota, rate limits, or the per-item time
  budget. When a budget runs out the worker writes `RUNSTATE.md`, pushes a WIP commit and reports `WAITING` with an observable resume condition; the orchestrator relaunches a fresh worker from it (see `fanout`).
- **Stop only when:** progress plateaus after a pivot, the next step is
  irreversible, or two reviewers still disagree after two rounds (show both
  positions to the owner).
- **Typed BLOCKED.** A stuck item reports `BLOCKED(env)`, `BLOCKED(task)` or
  `BLOCKED(decision)` and the queue moves on to the next item.

## Quota fallback order

`quota-gate` runs before every launch (see the quota-fallback PR).

1. Subscriptions first (Claude, then Codex). Use them fully.
2. When Claude is at 0%, fall back to Codex with a written handoff
   (`RUNSTATE.md` + brief), not by silently switching mid-thread.
3. Lower-priority subscriptions (e.g. Antigravity) only after those.
4. Pay-per-token routers (e.g. OpenRouter/DeepSeek) are a last resort with a
   hard daily cap, configured the same way for every agent profile.
5. Metered API-credit keys are used only when the owner explicitly asks.

When everything is at 0%: pause and resume after the reset. Never fail the ticket
for quota.

Known gap: some harnesses cannot hand a running thread to another model. In that
case the fallback starts a new thread from `RUNSTATE.md` instead of continuing in
place.

## Parallel batches (optional)

A batch runner may run several items at once when they do not touch the same files.

- **File set per item.** Each brief declares `Touches: path, dir/, glob/*.py`, or a
  read-only dry plan derives it and caches it. No file set means the item is
  exclusive and runs alone.
- **Conflict groups.** Overlapping items run one after another; disjoint items run
  concurrently, each in its own git worktree and branch, with its own log,
  `RUNSTATE.md` and PR.
- **Concurrency cap.** Default 3 (`RUNNER_MAX_PARALLEL`; set it to 1 for serial runs).
- **Rate-limit backoff.** A provider 429 halves the cap and requeues the item; the
  cap climbs back one step at a time after a cooldown.
- **Quota before each start.** When the provider is at 0%, start nothing new, let
  running items finish, and notify the owner.
- **Idempotent.** Items already marked done are skipped on relaunch; a BLOCKED
  item is retried and a WAITING item is resumed from its `RUNSTATE.md`.

## Orchestrator conventions (product-owner layer)

These live in the orchestrator that dispatches jstack workers, documented here
because workers rely on them:

- **One thread per ticket.** A ticket never shares a worker thread; reruns
  reuse the ticket's own thread.
- **Briefs carry a done-when state.** Every brief states the observable state
  that means done, so the worker and the reviewer judge the same thing.
- **Idempotent approval cards.** Re-sending a decision request never creates a
  duplicate; an answered card is recorded before anything else.
- **Heartbeat without an LLM.** Status pulses are computed from tracker and git
  state, not generated by a model call.
- **Settle and clean up.** After a worker finishes, its thread is settled and
  its worktree/branch cleaned once integrated.
- **backlog-next.** When the queue empties, the next item comes from the
  product's ranked backlog, not from ad-hoc picks.
